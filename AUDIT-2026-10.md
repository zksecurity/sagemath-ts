Continues AUDIT-2026-09.md. Full audit remains open; TODO.md tracks the handoff.

## October 1 — small-prime initialization and scalar backends (28.0.0)

Read PARI elliptic.c:773–810/2289–2316. Integer domains two and three must use
FF records; the prior adapter returned integer/Fp records, threw for singular
curves and left short ternary multiplication on the local Jacobian fallback.
The entry point now delegates to the existing native FF initialization and
scalar ports. The mutable short-record cache handles both model families and
unwraps degree-one coordinates at the short-point API boundary. The unused
local scalar fallback was removed.

The public ellinit result type is now an integer/FF/null union for a general
bigint domain, with precise domain-free and literal small-prime overloads.
Existing valid p>3 test/caller records are explicitly narrowed. Field accessors
preserve scalar types. ellisnonsingular previously compared a field-element
object to bigint zero, incorrectly accepting singular FF records; it now tests
the actual field value. Existing native singular-record cases now compare this
predicate as well as coefficients, discriminant, j, model and domain type.

Twelve new compact controls and fresh generators compare integer-domain
initialization, singular returns, binary/ternary scalar outputs, optimized Sage
caller state/coercion and mutable short-record cache reuse. Before the repair,
all 87 new small-prime initializer checks failed (4253424393/2030400033,
runs=40). The native oracles remain temporary executables, with no stored outputs.

Final validation: 3,033 existing/general/optimized model comparisons
(3072025758/runs=300), 1,869 odd comparisons (3611305920/runs=300), and 1,834 binary
comparisons (1607498517/runs=300). All 267 affected unit tests and 391 docs/storage
checks pass. All eight builds pass. All 568 complete normalized diagnostic blocks
match the frozen typecheck baseline; no baseline refresh. Versions are 28.0.0.

Remaining: finite-field order/cardinality/group backends, native input coercion
and API boundaries, torsion and remaining module inventory. Singular ellinit
outside p=2/3 retains its older exception behavior, explicitly tracked in
DEVIATIONS.md. Returning a native FF record does not establish the missing group
backends. Next dependency: bb_group.c gen_order and the three extension order
wrappers; cardinality additionally needs native Satoh/Kohel/Harley/Kedlaya/SEA
branches rather than an exhaustive substitute.


## October 1 — supplied-bound extension point orders (28.1.0)

Ported bb_group.c:560–578/668–713, then FlxqE.c:313, FpE.c:1727,
F2xqE.c:298 and ff.c:1495. gen_order preserves native recursive factor splitting,
identity-test/power callback ordering, factorized inputs and the native unchecked
annihilating-bound precondition. FF_ellorder first applies the original-to-native
coordinate change. These functions do not count curves or synthesize a bound.

The existing prime FpE_order used a different factor-stripping loop and custom
errors for nonpositive bounds. It now delegates to gen_order too; direct native
ellorder controls compare the corrected PariError messages and infinity shortcut.

Twenty-six compact controls and fresh recipes compare generic callback traces,
integer/matrix/vector order forms, missing/invalid bounds, binary ordinary and
supersingular models, ternary ordinary/supersingular models, other odd fields,
and a 127-bit base prime with a 128-bit annihilating bound. Small-field random
point inputs derive a6 and use a test-only LCM of the Hasse interval as the known
bound; production never enumerates points or the Hasse interval. Live field
oracles invoke FF_ellorder and its native kernels. No transcript corpora are saved.
The oracle clones callback trace entries across PARI stack compaction and releases
those clones after both successful and failed calls.

Validation: 2,792 odd/order comparisons (3735502017/runs=300), 2,137 binary
comparisons (3581189061/runs=300), 3,033 prime/caller comparisons
(140665291/runs=300), 52 group unit tests and 392 docs/storage checks pass. All
eight builds pass. Full normalized typecheck blocks match all 568 baseline
entries, without refresh. Versions are 28.1.0.

Remaining: native cardinality dispatch/algorithms, group structure/exponent,
default field point-order callers, and the rest of the audit checklist. The
provided-bound APIs and dependency wrappers are complete within their documented
input contract; they do not establish full field-group or elliptic coverage.


## October 1 — base-field extension counting dependencies (28.2.0)

Read FpE.c:2046–2062 and the callers in FpE.c:2187 and FlxqE.c:1457.
Ported elltrace_extension by representing the quadratic quotient with an exact
coefficient pair and using gen_powu_i; this preserves logarithmic degree
powering. Fp_ffellcard counts the base curve, derives its Frobenius trace, and
extends that trace. These helpers do not enumerate extension points.

Seven compact controls and fresh cases compare the native exported routines,
including degree zero, negative traces, large integer inputs and small-prime
curve coefficients. Expanded suite: 3,399 comparisons (350107974/runs=300).
All 393 docs/storage checks and eight builds pass. Complete normalized diagnostic
blocks match all 568 baseline entries. Versions are 28.2.0.

The existing prime counter is reused and retains its known dispatcher gap:
FpE.c:1424 selects SEA at expi(p)>=56, whereas the older port defaults to Shanks
and switches to base Schoof at 96 bits despite an available separate SEA port.
Word-Shanks versus arbitrary-prime dispatch also needs review. Other extension
branches require native j/minimal-polynomial descent, binary trace algorithms,
ternary special formulas and the corresponding square-root implementation,
p-adic counting, Shanks and extension SEA. In particular, Flxq_sqrt in
Flx.c:3715–3783 differs from FF_issquareall's nth-root path; substitution without
comparing native root selection is inappropriate. TODO.md records the next steps.


## October 1 — native prime SEA dispatch (28.2.1)

Default ellcard now selects SEA at expi(p)>=56 after CM, matching FpE.c:1424.
Previously the port used Shanks below 96 and base Schoof above it despite an
existing SEA backend. A compiled copy of the exact bundled native dispatcher
with traced backend stubs exposed 12 mismatches before the fix (seed148627348).
The dispatch oracle maps both Shanks kernels to one category; it does not claim
word-kernel equivalence. Composite threshold inputs are dispatch-only tests.

Six compact branch controls and two actual prime-count controls were added.
Fresh branch recipes cover both threshold boundaries, coefficient reduction and
CM priority. Actual live counts exercise SEA at 61 and 64 bits, including a
degree-two extension count. 3,707 comparisons (3930526672/runs=300), 393
docs/storage checks and eight builds pass. Complete normalized diagnostic blocks
match all 568 baseline entries. Versions are28.2.1; no bulk artifacts retained.

Still open: Fl_ellcard_Shanks uses a different affine word-point/baby-step search
than the port's arbitrary-integer Shanks kernel. Port its dependencies before
claiming native middle-range scheduling, then continue extension dispatch.

arith1.c:750–856. Implemented direct Flxq_sqrt/pre with the native quadratic,

random-state fingerprints. Nonmonic quadratic API validity is not established.

(4270696682/runs=40) and 395 docs/storage tests pass. All eight builds pass;
