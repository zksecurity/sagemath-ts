# sagemath-ts Audit — July 2026

Adversarially verified audit of the TypeScript port against the vendored upstream at
`reference/` (sage, pari, flint, ntl, sage_blueprints). Every finding below was confirmed
by reading the upstream source **and**, in almost all cases, by executing the port and
producing a counterexample.

## Summary

**370 confirmed findings.**

| Severity | Count |
|---|---|
| Critical | 17 |
| High | 120 |
| Medium | 153 |
| Low | 80 |

| Category | Count |
|---|---|
| bug (mathematically wrong answer / hang / crash) | 170 |
| infidelity (different shape, error, default, edge case) | 108 |
| missing-test | 32 |
| undocumented-deviation | 24 |

| wrong-data (bad hardcoded tables/values) | 9 |

**Assessment.** The port's *surface* is broad and its *core* is frequently right — factorization
over prime fields, Buchberger, point arithmetic, `exact_log`, class-number tables, LAT/DDT values,
Weil/Tate pairing bilinearity and many other non-trivial algorithms reproduce SageMath's doctests
exactly. But fidelity degrades sharply the moment a code path leaves the happy case that its own
test exercised: 170 confirmed wrong-answer defects, including a global RNG whose low-bit LCG output
makes every sampler emit short deterministic cycles, seven *reducible* entries in the Conway
polynomial table (so `GF(29^2)` is not a field), a sign error in `Vélu`'s y-coordinate that puts
isogeny images off the codomain, and a minimal-polynomial routine that returns the minimal
polynomial of `e_0` rather than of the matrix. A recurring structural cause is hand-rolling
primitives that CLAUDE.md requires be delegated (PARI `Z_factor`/`isprimepower`/`qfbcompraw`/
`ellcard`, NTL `BuildSparseIrred`, FLINT `xgcd`) — `flint-ts` and `ntl-ts` are 100% stubs, so
`sagemath-ts` reimplements them badly rather than delegating. The second recurring cause is
floating point where Sage is exact: LLL, free-module `coordinates`/`echelonize`/`discriminant`,
lattice Gram-Schmidt and `real_log` all round doubles back into `bigint`. Finally, the test suite
is systematically unable to detect these: every suite is green, and in many files the tests pin
the *wrong* value (`is_discriminant(4) === false`, `round(-3.5) === -3n`, `buildIrred(1).bits === 3n`,
`smallest_integer() === 4n`, `degrees() === [-1,-1,-1]`, `pNorm(2) === 25n`).

## Critical and High Findings

### C1 — `packages/sagemath-ts/src/misc/randstate.ts:107` — RNG returns short deterministic cycles
**Sage:** `randstate.pyx:511` `gmp_randinit_default` (Mersenne Twister); `:881` `gmp_urandomb_ui`.
**Port:** `random_bits()` takes the **low** `bits` bits of a Knuth MMIX LCG mod 2^64. For an LCG mod 2^64,
bit *k* has period 2^(k+1), so the low *b* bits repeat a fixed cycle of length 2^b forever.
**Evidence:** `new RandState(7).random_below(4n)` ×40 → `"2130213021302130…"`; `random_below(2n)` → perfectly
alternating `101010…`; `randint(0n,9n)` has period 10. Downstream: 200 000 samples of
`DiscreteGaussianDistributionIntegerSampler({sigma:3})` never emit x ∈ {−9,−8,−6,−4,1,3,6,8,10,11,13}.
Consumers: `integer_ring`, `rational_field`, `finite_field_prime`, `integer_mod_ring`, `groups/generic`, `crypto/lwe`.
**Fix:** take the **high** bits (`next_uint64() >> (64n - BigInt(chunkBits))`), or port GMP's Mersenne Twister.

### C2 — `packages/sagemath-ts/src/rings/finite_rings/conway_polynomials.ts:106` — 7 table entries are reducible
**Sage:** `conway_polynomials.py:22-64` — every database entry is monic, **irreducible** and primitive.
**Port:** `CONWAY_POLYNOMIALS[5][6], [7][5], [13][4], [17][3], [23][3], [29][2], [31][2]` are reducible;
`getDefaultModulus` (`finite_field_extension.ts:644-651`) feeds them straight to the quotient construction.
**Evidence:** independent irreducibility check flags exactly those 7 (39 others pass). `GF(29^2)` → modulus
`a^2+27a+2`, and `(5a+26).inv()` throws "element is not invertible (modulus not irreducible)". Likewise
`GF(31^2)`, `GF(7^5)`, `GF(5^6)`. Not covered by the "Conway Polynomial Database Limited" deviation.
**Fix:** replace with the true values: `5^6 → [2,0,1,4,1,0]`, `7^5 → [4,1,0,0,0]`, `13^4 → [2,12,3,0]`,
`17^3 → [14,1,0]`, `23^3 → [18,2,0]`, `29^2 → [2,24]`, `31^2 → [3,29]`. Add a test asserting every entry is
irreducible **and** primitive.

### C3 — `packages/sagemath-ts/src/rings/rational.ts:60` — `integerNthRoot` never terminates
**Sage:** `rational.pyx:2075/2137` delegate to `Integer.nth_root` → GMP `mpz_root`, which always terminates.
**Port:** `while (root !== prevRoot)` on `root = ((n-1)root + x/root^(n-1))/n` enters a 2-cycle for most
non-perfect powers; the termination test compares only against the immediately previous value.
**Evidence:** `new Rational(4n,1n).is_nth_power(3n)` hangs (killed at 8 s). Standalone loop with a 500-iteration
cap: 4180/12000 inputs (x ∈ [1,2000], n ∈ [3,8]) never converge. Trace for x=4,n=3: 4 → 2 → 1 → 2 → 1 …
**Fix:** monotone binary search, or break when `newRoot >= root` and correct downward (mpz_root's stopping rule).

### C4 — `packages/sagemath-ts/src/rings/polynomial/polynomial_element.ts:1393` — `is_irreducible` misses most reducibles
**Sage:** `polynomial_element.pyx:10182-10196` — `F = self.factor(); return len(F)==1 and F[0][1]==1`.
**Port:** the distinct-degree loop only runs the gcd test when `n % d === 0`, and never verifies `x^{q^n} ≡ x`.
A squarefree reducible f of degree n always has a factor of degree d ≤ n/2, but d need not divide n.
**Evidence:** GF(2): `(x^2+x+1)(x^3+x+1) = x^5+x^4+1` → `is_irreducible() === true` while `factor()` correctly
returns both factors. Also `x^5+x+1` → true. GF(5): `(y^2+2)(y^3+y+1)` → true.
**Fix:** drop the `n % d === 0` guard (test every d with 2d ≤ n), or mirror Sage and use `factor()`.

### C5 — `packages/sagemath-ts/src/rings/polynomial/multi_polynomial_ring.ts:230` — `R(f)` misclassifies polynomials
**Sage:** `multi_polynomial_ring.py:175` — `R(f)` for f already in R is identity coercion.
**Port:** `isBaseRingElement()` (`:405-419`) duck-types on `add/sub/mul/neg/eq/isZero`, all of which `MPolynomial`
implements, so line 230 fires first and wraps the polynomial as the coefficient of the zero exponent. The
dedicated `x instanceof MPolynomial` branch at `:242` is unreachable dead code.
**Evidence:** `R.__call__(x^2+y)` → keys `["0,0"]`, `degree()===0`, `isConstant()===true`, `eq(f)===false`;
cross-ring `g.mul(R3.gen(2))` → `TypeError: undefined is not an object (evaluating 'other.terms')`.
**Fix:** move the `instanceof MPolynomial` check above `isBaseRingElement`, return `x` when `x.parent === this`,
re-pad exponent keys to `ngens_value`, and exclude MPolynomial/Polynomial from `isBaseRingElement`.

### C6 — `packages/sagemath-ts/src/rings/padics/padic_generic_element.ts:1126` — p-adic `add()` multiplies by p^v twice
**Sage:** `CR_template.pxi` `_add_`/`cadd` aligns operands at the common valuation and adds units once.
**Port:** `thisLift = unit * p^max(val,0)` already contains p^v; lines 1131-1132 multiply again by `p^(val-minVal)`,
giving `unit * p^(2*val - minVal)`.
**Evidence:** `Zp(5,10)(10) + Zp(5,10)(15)` → lift `125n` (correct 25); `Zp(5,10)(25)+Zp(5,10)(1)` → `1 + 5^4`
(correct `1 + 5^2`); `Zp(7,10)(7)+Zp(7,10)(14)` → 147 (correct 21). Poisons `exp`, `log`, everything downstream.
**Fix:** drop the `bigPow(p, val)` factor from `thisLift`/`otherLift`; use `unit * p^(val - minVal)`.

### C7 — `packages/sagemath-ts/src/rings/complex_mpfr.ts:363` — complex `sqrt` returns √(conj z)
**Sage:** `complex_mpfr.pyx:3029-3052` — avoid_branch path does `mpfr_swap` so `re = b` (NOT negated) and
`im = a`, negating **both** parts only when Im(z) < 0.
**Port:** `const tempA = a; a = -b; b = tempA;` negates the real part; the result squares to `conj(z)`.
**Evidence:** `CC(-3,1).sqrt()` = `-0.2848…+1.7553…i`, whose square is `-3 - 1i`. Same for (−3,−1), (−1,0.5),
(−5,2). Contaminates `arccos`: `CC(-2,0.5).arccos()` has real part outside [0,π].
**Fix:** in the avoidBranch branch set `re = b; im = a` (no negation), then negate both if y < 0.

### C8 — `packages/sagemath-ts/src/matrix/matrix_operations.ts:1552` — `minpoly` returns the minpoly of e₀
**Sage:** `matrix2.pyx:3070-3130` — charpoly, squarefree test, else radical + per-factor exponent from kernel
dimensions; `matrix2.pyx:3133-3145` asserts `minpoly(A)(A) == 0`.
**Port:** builds the Krylov sequence from the fixed start vector `e_0` and reads the first dependence from the RREF —
the minimal polynomial of a *vector*, a proper divisor of the true minpoly whenever e₀ is not cyclic.
**Evidence:** GF(7): `minpoly(diag(1,2))` = `x + 6` (Sage `x^2+4x+2`); `minpoly(diag(1,2,3))` = `x+6`;
`minpoly([[1,1],[0,1]])` = `x+6` (Sage `(x-1)^2`). The result does not annihilate the matrix.
**Fix:** port Sage's algorithm (charpoly → squarefree test → radical + kernel-dimension exponents), or take
the lcm of vector minimal polynomials over a spanning set.

### C9 — `packages/sagemath-ts/src/matrix/matrix_integer.ts:919` — `smith_form_integer` infinite loop
**Sage:** `matrix_integer_dense.pyx:2407` delegates to PARI `matsnf`; always terminates.
**Port:** the `while (changed)` loop alternates row/column elimination. When `extendedGcd` returns (s,t)=(0,±1)
(whenever one argument divides the other) the "elimination" is a swap, not a reduction, and the two phases undo
each other forever.
**Evidence:** `smith_form_integer([[-1,-1,-1],[-1,-1,-1],[0,-1,-1]])` never returns (timeout, exit 124); ditto
`rank_integer` on it and `smith_form_integer([[4,6,-5,-4],[3,-1,1,0],[-4,3,5,-1]])`. Instrumented copy shows a
1-pass fixed cycle with `changed` unconditionally re-set. Hangs `elementary_divisors`, `rank`, `kernel_matrix`,
`saturation`, `symplectic_form`.
**Fix:** when `g == |A[k][k]|` just subtract the multiple; add a guard that `|A[k][k]|` strictly decreases each pass;
ideally delegate to a `matsnf` port.

### C10 — `packages/sagemath-ts/src/matrix/matrix_modn.ts:539` — `charpoly` sign error (Faddeev–LeVerrier)
**Sage:** `matrix_modn_dense_template.pxi:1443-1447` — LinBox for prime p>2, else `Matrix_dense.charpoly`; both `det(xI-A)`.
**Port:** `const c = mod(-coeffs[n-1-i], modulus)` — the recurrence `M_k = A(M_{k-1} + c I)` requires **adding** the
coefficient. (`matrix_integer.ts:1480` gets the same recurrence right.)
**Evidence:** GF(101): `charpoly(diag(2,3))` = `[82n,96n,1n]` (correct `[6n,96n,1n]`); `[[1,1],[0,1]]` → `[98n,99n,1n]`
(correct `[1n,99n,1n]`). Cayley–Hamilton fails: p(A) = 76·I. `minpoly` inherits it.
**Fix:** `const c = coeffs[n-1-i]` (no negation), or use the division-free Hessenberg algorithm.

### C11 — `packages/sagemath-ts/src/matrix/matrix_modn.ts:786` — `right_kernel_matrix` echelonizes the transpose
**Sage:** `matrix_modn_dense_template.pxi:2072-2176` echelonizes `self`, uses `self.pivots()`, builds the basis
from non-pivot columns, then echelonizes the basis.
**Port:** `const At = this.transpose(); const echelon = At.echelon_form();` and then indexes `echelon[r][freeCol]`
with column indices of the **original** matrix.
**Evidence:** GF(7): `[[1,2],[3,6]].right_kernel_matrix()` = `[4 1]`, but `A·[4,1]^T = [6,4]^T ≠ 0`
(true kernel `[5,1]`). `[[1,1]]` throws `TypeError: Invalid mix of BigInt and other type in remainder`.
Even the passing 6×6 case returns the `pivot` basis, not Sage's default `echelon` basis.
**Fix:** echelonize `this`; kernel rows `v[freeCol]=1`, `v[pivotCol_r] = -E[r][freeCol]`; echelonize the result.

### C12 — `packages/sagemath-ts/src/modules/free_module.ts:2326` — `span()`/`subspace()` use #generators as the rank
**Sage:** `free_module.py:1586+` — the basis is the echelon form of the generating matrix; rank is the true rank
(doctest `:1641-1646`: 3 generators → rank 2).
**Port:** `const rank = gens.length; // Simplified: assumes linearly independent` and `this._basis = this._userBasis`,
with no echelonization. `FreeModuleSubspaceWithBasis` ignores its `echelonize: true` option.
**Evidence:** `span([[1,2,3],[2,4,6]], ZZ).rank()` → 2 (Sage 1); `VectorSpace(QQ,3).subspace([(1,2,3),(2,4,6)]).dimension()`
→ 2 (Sage 1). Corrupts dimension, codimension, discriminant, gram_matrix, coordinates, index_in.
**Fix:** compute the true rank and an echelonized basis (HNF over ZZ via `matrix_integer.hermite_normal_form`,
RREF over a field) when constructing a span.

### C13 — `packages/sagemath-ts/src/modules/free_module_integer.ts:1498` — `lllReduce` diverges then crashes
**Sage:** `matrix_integer_dense.pyx:3302` delegates to fpLLL/NTL with precision escalation; always returns a basis
of the same lattice.
**Port:** the entire Gram–Schmidt runs in IEEE doubles (`computeGramSchmidt`, `:1534-1580`). Above ~2^26 entries the
dot products exceed 2^53, μ degenerates, and `BigInt(Math.round(mu))` at `:1644` receives NaN.
**Evidence:** `IntegerLattice(genLattice({type:'random',n:1,m:30,q:2n**40n,seed:42}))` → `RangeError: Not an integer`
at `:1644`. q-ary sweep (q=2^30): m=10 and m=12 return bases for which the port's **own** `isLLLReduced` is false
(22-digit entries); m ∈ {14,16,18,20,25,30} all throw. q=1024 works to m=40, so the trigger is entry magnitude.
**Fix:** exact integer/rational Gram (or bigint-backed high precision) for the GSO; add incremental size reduction
(`mu[k][i] -= q*mu[j][i]`); detect non-finite μ instead of calling `BigInt(NaN)`.

### C14 — `packages/sagemath-ts/src/quadratic_forms/binary_qf.ts:358` — Gauss squaring is wrong
**Sage:** `binary_qf.py:260` → PARI `qfbcompraw`. PARI `qfb_sqr` (`Qfb.c:1014-1035`): `d1 = bezout(b,a,&x2,NULL)`;
if `d1 != 1` then `v1 = a/d1`, **`v2 = v1*gcd(d1,c)`**, **`c *= d1`**; `r = m mod v2`, `p1 = r*v1`, `z1 = v1*v2`,
`z3 = c3/v2`.
**Port:** sets `v1 = a/d; v2 = a` unconditionally, never applies `gcd(d1,c)` or `c *= d1`, reduces `r = m % v1` and
uses `p1 = r*v2`, `newA = (a/d)*a`. Agrees with PARI only when `gcd(a,b) = 1`.
**Evidence:** `BinaryQF(2,2,3).compose(BinaryQF(2,2,3))` → (2,2,3), reduced (2,2,3). Sage: `x^2+5y^2` = (1,0,5).
D = −20 has h = 2 and (2,2,3) is the order-2 class, so its square **must** be principal.
**Fix:** port `qfb_sqr` verbatim, or add `qfbcompraw` to parigp-ts and delegate.

### C15 — `packages/sagemath-ts/src/quadratic_forms/binary_qf.ts:174` — `reduced_form` returns non-reduced forms
**Sage:** reduction via PARI `qfbred` normalizes b into (−a, a]; `is_reduced` requires `-a < b <= a < c`.
Doctest `binary_qf.py:915-916` asserts `BinaryQF([-225,-743,-743]).reduced_form().is_reduced()` is True.
**Port:** the normalization step is guarded by `if (b < -a || b > a)`, which **excludes b == −a**. The
negative-definite path routes through the same helper.
**Evidence:** `BinaryQF(2,-2,5).reduced_form()` → (2,−2,5), `is_reduced() === false` (Sage: (2,2,5)). Sage's own
doctest input `BinaryQF(-225,-743,-743)` → (−157,−157,−225), `is_reduced() === false`. Random sweep: 42/1105
positive-definite forms come back non-reduced.
**Fix:** normalize b into (−a, a] unconditionally, e.g. `s = floor((a - b)/(2a))`. **Note:** the naive
one-character change `b <= -a` does *not* work — with b = −a the existing s computation yields s = 0.

### C16 — `packages/sagemath-ts/src/schemes/elliptic_curves/ell_curve_isogeny.ts:1455` — Vélu y-formula wrong
**Sage:** `ell_curve_isogeny.py:2094-2103` — `tY = tY0*inv_t1_3 + (tY1 + tY2)*inv_t1_2`, then `Y -= tY`.
**Port:** `tY0.mul(inv_t1_2).add(tY1.mul(inv_t1_2)).sub(tY2.mul(inv_t1_2))` — divides tY0 by `(x-xQ)^2` instead of
`(x-xQ)^3` and **subtracts** tY2.
**Evidence:** Sage doctest curve `E = EllipticCurve(GF(7),[0,0,0,-1,0])`, `P = (4,2)`: degree and codomain are right,
but every non-kernel image fails `codomain.is_on_curve`: `phi(0,0) = (0:6:1)` (Sage `(0:0:1)`), `phi(5,1)`,
`phi(5,6)`, `phi(6,0)` all off the curve.
**Fix:** `const tY = tY0.mul(inv_t1_3).add(tY1.add(tY2).mul(inv_t1_2)); Y = Y.sub(tY);`

### C17 — `packages/parigp-ts/src/elliptic/group.ts:841` — `ellcard` returns a wrong cardinality
**Sage/PARI:** `Fp_ellcard_Shanks` (`FpE.c:939`) uses `pordmin = sqrti(4p<<2)+1` (a true ceiling of 4√p), seeds
(A,B) from 2-torsion (`:944-948`), alternates with the quadratic twist (`:952-963`), and short-circuits c6=0 to
`ap_j1728` (`:930-934`).
**Port:** `hasseBound = 2n*isqrt(p)` (truncating), giant-step hits filtered by `<= center + hasseBound`, no twist
alternation, no 2-torsion seeding, and it returns `closest_lift` even when B < pordmin.
**Evidence:** exhaustive point count vs `ellcard` over 420 curves (p ∈ [1009,1069]): **6 wrong**, e.g.
p=1063,a4=0,a6=3 → 1064 (true 1129); p=1069,a4=0,a6=1 → 1092 (true 1008); p=1013,a4=2,a6=0 → 1012 (true 1058).
Propagates into `ellorder`, `ellgroup`, `ellgenerators`, `elllog`.
**Fix:** `hasseBound = isqrt(16n*p)+1n`; drop the `<= center + hasseBound` filter; implement twist alternation and
2-torsion seeding; add the c6 = 0 / `ap_j1728` case; throw when B < pordmin.

### High — `arith/misc.ts`

**H1 — `arith/misc.ts:865` — `kronecker_symbol` never returns 0 for even a.**
Sage (`arith/misc.py:4313`) delegates to `Integer.kronecker` → GMP `mpz_kronecker`, which is 0 whenever
gcd(a,n) > 1 because (a|2) = 0 for even a. The port's `v > 0` branch applies only the a-mod-8 sign rule and
never tests the parity of a. Ran: `kronecker_symbol(2,2)=1`, `(2,4)=1`, `(2,6)=-1`, `(10,12)=1`, `(0,2)=1` —
all should be 0; 752/3721 mismatches over a,n ∈ [−30,30]. Propagates to `legendre_symbol`/`hilbert_symbol`.
*Fix:* return `0n` immediately when a is even in the `v > 0` branch.

**H2 — `arith/misc.ts:608` — `is_prime_power` calls a hard semiprime prime.**
Sage (`integer.pyx:5399-5434`) uses PARI `isprimepower` (perfect-power extraction + BPSW), no factorization.
The port calls `trial_division`, and when `Z_factor` gives up it returns n, so the `p === _n` branch
("shouldn't happen") returns true. Ran with p,q ≈ 10^24: `is_prime_power(p*q) === true` (Sage False),
`is_prime_power(p*p, true) === [p*p, 1n]` (Sage `(p,2)`). *Fix:* port `Z_isanypower`/`isprimepower` to parigp-ts
and delegate; never infer primality from a failed factorization.

**H3 — `arith/misc.ts:1961` — `is_pseudoprime` uses fixed MR bases, not BPSW.**
Sage (`arith/misc.py:607` → `integer.pyx:5607`) uses PARI `ispseudoprime` (BPSW). The port runs Miller–Rabin
against the first 12 primes — and 318665857834031151167461 is the smallest composite passing exactly those.
Ran: `is_pseudoprime(318665857834031151167461n) === true` (composite; the port's own `is_prime` says false);
`next_probable_prime(…459n)` returns that composite. *Fix:* delegate to the same BPSW entry point `is_prime` uses.

**H4 — `arith/misc.ts:2485` — `CRT_basis` wrong for ≥3 non-coprime moduli.**
Sage (`arith/misc.py:3713-3726`) builds `e_i = CRT(0,1,M_i//d_i,m_i//d_i)` plus a partial-product table; for
[60,90,150] this gives cs = [15,−20,6] and `CRT_list([32,2,2],[60,90,150]) = 452`. The port's ad-hoc xgcd
recurrence gives [885,300,180]; the combination 29280 is 0 mod 60 (want 32). `CRT_vectors([[32],[2],[2]],[60,90,150])`
throws "solution does not exist". Two moduli happen to work, so tests pass. *Fix:* transcribe Sage's algorithm.

### High — `rings/integer_ring.ts`, `rings/rational*.ts`

**H5 — `integer_ring.ts:369` (also `:361`, `:1347`) — truncating instead of floor division.**
Sage uses `mpz_fdiv_qr` (`integer.pyx:3612`) and `mpz_fdiv_q` (`:2201`); doctest `Integer(231).quo_rem(-2) == (-116,-1)`
and `100 // int(-3) == -34`. Port returns `[a/b, a%b]` with BigInt truncation. Ran: `(-5).quo_rem(3)` → `[-1,-2]`
(Sage `(-2,1)`); `231.quo_rem(-2)` → `[-115,1]`; `(-231).__floordiv__(2)` → −115; `100.__floordiv__(-3)` → −33.
Zero test coverage; no DEVIATIONS entry. *Fix:* `q = a/b; if (a%b !== 0n && (a<0n)!==(b<0n)) q -= 1n; r = a - q*b`;
raise `ZeroDivisionError('Integer division by zero')` for b = 0.

**H6 — `rational_field.ts:602` — `quadratic_defect` wrong for non-integral input and negative odd valuation.**
Sage (`rational_field.py:1490-1504`) tests `v % 2 == 1` with Python's non-negative `%`, passes the **rational**
unit to `legendre_symbol` (which uses `numerator*denominator`, `arith/misc.py:4365`) and reduces `u % 8` via
`Rational.__mod__`. The port tests `v % 2n === 1n` (false for v = −1 under BigInt) and uses `u.numerator` only.
Ran: `QQ.quadratic_defect(1/3,7)` → Infinity (Sage 0); `(1/3,2)` → Infinity (Sage 1); `(1/5,5)` → Infinity (Sage −1).
*Fix:* `((v%2n)+2n)%2n === 1n`; pass `num*den` to legendre_symbol; compute u mod 8 with `inverse_mod(den,8n)`.

**H7 — `integer_ring.ts:1407` — `nth_root_mod` rejects solvable instances.**
Sage's `_nth_root_common` (`element_base.pyx:29`) returns a root whenever `a^((p-1)/gcd(n,p-1)) == 1` — exactly the
residue test the port already passes. The port's hand-rolled prime-power loop (`:1470-1510`, `k !== v` branch) then
